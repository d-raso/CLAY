The **galaxy-layer generation scheme** lives in `Assets/_Scripts/Galaxy/` (namespace `CLAY.Galaxy`), added 2026-08-16. Implements design-doc `Assets/Design/PlanetaryParameters.md` §1–4 (star → habitability → planet types/distances). "Largely follows Universe Sandbox" — real main-sequence astrophysics.

Files:
- `Astrophysics.cs` — `SpectralClass` enum (O–M) + `Classes` table (mass ranges + IMF abundance weights: M 0.764, K 0.121, G 0.076, …), and the physics: `MassToLuminosity` (piecewise L∝Mᶜ), `MassToRadius`, `EffectiveTemp` (Stefan–Boltzmann, clamp 2400–52000 K), `LifetimeGyr` (10·M/L), `HabitableZone` (√(L/1.1)…√(L/0.53) AU), `BlackbodyColor` (Tanner-Helland), `Designation` (subclass 0–9 from T), plus `Smoothstep`/`Bell`.
- `DetRng.cs` — SplitMix64 deterministic RNG **struct** (seed → reproducible system; `DetRng.Hash(galaxySeed, index)` for populations).
- `StarData.cs` — star params + `Suitability()` → `StellarSuitability{lifetime,radiation,flares,overall}` (the habitability constraints the star imposes: O/B/A die young, hot stars = UV, M dwarfs = flares).
- `PlanetData.cs` — `PlanetType`{Terrestrial,Ocean,Desert,GasGiant,IceGiant,FrozenRock}, `HabClass`{Habitable,Marginal,Hostile,NotViable}, params + derived meanTempC/insolation/habitabilityIndex.
- `StarSystem.cs` — star + List<PlanetData>.
- `SystemGenerator.cs` — `Generate(seed, forceClass?)` and `GeneratePopulation(count, galaxySeed)`. Rolls class by IMF; planets spaced geometrically with snow line = 2.7√L (rocky inside / gas-ice outside); habitability = typeScore×tempScore(liquid water)×massScore(atmosphere)×presScore×stellarSuitability.
- `GalaxyGenDebug.cs` — MonoBehaviour test harness; right-click component → "Generate one system" / "Sample stellar population (distribution)". Logs to console.

**Verified 2026-08-16**: compiles clean; population of 2000 gave realistic IMF (M 78.95%, K 12.25%, A 0.45%, B 0.10%, O 0%) with 35.3% of systems having ≥1 habitable world. Example M3V: 0.28 M☉, 224 Gyr lifespan, HZ 0.11–0.15 AU, suitability 63% (flare-limited). NOTE this is pure data/logic — NOT yet wired to gameplay: still to do = design-doc §3 remaining planet physical params (atmoComposition, liquidType, volcanism…), §4 gameplay derivation (tidePoolCount, carryingCapacity → into `PlanetaryEnvironment`), §5 catastrophe profile, and any galaxy visualization. A standalone HTML prototype ("Star Forge" artifact) was built first then set aside — the C# module is the real deliverable.

Multiple stars (2026-09-26): `StarSystem.binary` (BinaryKind Single/Close/Intermediate/Wide). Companion mass = q × primary (coeval age & [Fe/H]); B's orbit is RELATIVE to A, C's is about the A+B barycentre. Planets come from `PlanetZones` with Holman–Wiegert limits (`StableSTypeFrac`, `StablePTypeMult`): close pair → circumbinary (hostStar = −1), else S-type zones around A and B (and a wide C). `PlanetData.hostStar / secondaryFlux / secondaryStarTempK`; insolation = flux from ALL stars; HZ & snow line tested on total flux (S_frost = 0.137). Viewer: `ComputeStarFrame` moves stars about the barycentre, planets orbit their host/barycentre with `sys.HostMass(p)`, brightest star = `_SunDir`, runner-up = `_Sun2Dir`(w = strength)/`_Sun2Col`/`_Sun1Col` in PlanetSurface/Atmosphere/Clouds. Surface gets a second directional Light + sky disc. Planet indices (and so HabitatRegistry keys / pseeds) shift in multi-star systems.
